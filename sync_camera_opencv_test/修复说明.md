# Python 客户端白屏问题修复说明

## 问题根源

**数据格式不匹配**：
- 🔴 **服务端发送**: H.264 编码的视频流
  ```
  appsrc (I420) -> x264enc -> h264parse -> tcpserversink
  ```
  
- 🔴 **Python 客户端接收**: 期望原始 I420 格式
  ```python
  # 错误的做法：直接按 I420 格式接收固定字节
  frame_data = sock.recv(width * height * 3 // 2)
  bgr_frame = self._i420_to_bgr(frame_data)
  ```

**结果**: H.264 编码数据被错误地当作 I420 原始数据解析，导致画面混乱（白屏）

## 为什么 ffplay 可以正常播放？

ffplay 会自动检测流格式并选择合适的解码器：
```bash
ffplay -i tcp://127.0.0.1:5010
# ffplay 自动识别 -> H.264 流 -> 使用 H.264 解码器 -> 正常显示
```

## 修复方案

使用 OpenCV 的 `VideoCapture` 直接连接和解码 H.264 TCP 流：

### 修改前 (错误)
```python
def _camera_capture_worker(self, port: int, camera_name: str):
    sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    sock.connect((self.host, port))
    
    while self.running:
        # 接收固定大小的 I420 数据
        frame_data = b''
        while len(frame_data) < self.frame_size:
            chunk = sock.recv(8192)
            frame_data += chunk
        
        # 手动转换 I420 -> BGR (错误！)
        bgr_frame = self._i420_to_bgr(frame_data)
```

### 修改后 (正确)
```python
def _camera_capture_worker(self, port: int, camera_name: str):
    # 使用 OpenCV 连接 TCP H.264 流
    stream_url = f"tcp://{self.host}:{port}"
    cap = cv2.VideoCapture(stream_url, cv2.CAP_FFMPEG)
    cap.set(cv2.CAP_PROP_BUFFERSIZE, 1)  # 最小缓冲，降低延迟
    
    while self.running:
        # OpenCV 自动处理 H.264 解码
        ret, frame = cap.read()
        if ret and frame is not None:
            # frame 已经是解码后的 BGR 格式
            self.latest_frames[camera_name] = frame.copy()
```

  - ✅ 删除不再需要的 `_i420_to_bgr()` 方法

## 技术优势

1. **自动解码**: OpenCV 内部调用 FFmpeg 解码 H.264
2. **格式兼容**: 与服务端 GStreamer 输出完全兼容
3. **代码简化**: 不需要手动处理 YUV 转换
4. **低延迟**: 设置最小缓冲区 (`BUFFERSIZE=1`)
